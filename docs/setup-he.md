המדריך מיועד לבעלים של האפליקציה. הוא לוקח כחצי שעה, ובסופו אפשר להתקין את האפליקציה בטלפון ובלפטופ ולהיכנס אליה.

| שלב | מה עושים | מי עושה |
|---|---|---|
| 1 | פרויקט Supabase חינמי, שבו נשמרים המשתמשים והמשימות | אתם |
| 2 | התחברות ל-GitHub מהמחשב | אתם |
| 3 | העברת פרטי החיבור של Supabase לאפליקציה | אני |
| 4 | מפתח חתימה לאפליקציית האנדרואיד | אני מריץ, ואתם מגבים את הקבצים |

| 6 | בסיס הנתונים למשימות (גרסה 0.2) ובדיקת האבטחה | אתם |

## שלב 1: פרויקט Supabase

1. היכנסו אל <https://supabase.com/dashboard> והירשמו. אפשר להירשם עם חשבון GitHub.
2. אם מתבקשת יצירת Organization, צרו אחד מסוג **Free**.
3. לחצו **New project** והגדירו:
   - **Name:** `moked`
   - **Database password:** לחצו **Generate a password** ושמרו את הסיסמה במנהל סיסמאות. האפליקציה לא משתמשת בה, אבל אי אפשר לשחזר אותה אחר כך.
   - **Region:** **Central EU (Frankfurt)**
   - **Plan:** Free
   - אם מוצגות אפשרויות נוספות, השאירו את ברירת המחדל.
4. לחצו **Create new project** והמתינו כמה דקות עד שהפרויקט מוכן.
5. **כבו הרשמה עצמית.** היכנסו ל-**Authentication**, ואז ל-**Sign In / Providers** (בגרסאות ישנות: **Settings**). חפשו את המתג **Allow new users to sign up**, כבו אותו ושמרו. בלי זה, כל מי שמגיע לאפליקציה יכול ליצור לעצמו משתמש.
6. **הריצו את קובץ ה-SQL.** היכנסו ל-**SQL Editor**, לחצו **New query**, והדביקו את כל התוכן של הקובץ `supabase/migrations/0001_profiles.sql` מהפרויקט. לחצו **Run**. אמורה להופיע ההודעה **Success. No rows returned**. מריצים פעם אחת בלבד.
7. **צרו את המשתמש הראשון.** היכנסו ל-**Authentication**, ואז **Users**, ואז **Add user**, ואז **Create new user**. הזינו אימייל וסיסמה חזקה (לפחות 10 תווים), וסמנו **Auto Confirm User**. המשתמש הזה הופך אוטומטית למנהל. משתמשים נוספים שתיצרו בלוח הבקרה נוצרים כלא פעילים ואינם רואים שום מידע. כדי להפעיל אחד מהם, פתחו את הטבלה **profiles** ב-**Table Editor** והדליקו את העמודה `is_active` בשורה שלו.
8. **ודאו שנוצר פרופיל.** היכנסו ל-**Table Editor**, ואז לטבלה **profiles**. אמורה להיות בה שורה אחת עם `role` = `admin`.
9. **העתיקו את פרטי החיבור.** לחצו **Connect** בראש הדף. העתיקו את **Project URL** (נראה כמו `https://xxxx.supabase.co`) ואת **Publishable key** (מתחיל ב-`sb_publishable_`).
10. שלחו לי את שני הערכים בצ'אט. הם ציבוריים בכוונה ובטוחים לשיתוף.

> **חשוב:** אל תשלחו לי ואל תדביקו בשום מקום את **Secret key** (מתחיל ב-`sb_secret_`) או מפתח בשם `service_role`. מי שמחזיק אותם יכול לקרוא ולשנות את כל המידע. האפליקציה מסרבת לעלות אם אחד מהם מופיע בהגדרות שלה.

## שלב 2: התחברות ל-GitHub

פתחו טרמינל והריצו:

```bash
gh auth login -s workflow
```

בחרו **GitHub.com**, ואז **HTTPS**, ואז **Login with a web browser**. הדביקו בדפדפן את הקוד שמוצג בטרמינל ואשרו. ההרשאה `workflow` (הדגל `-s workflow`) נחוצה כדי שאוכל לדחוף את קבצי הבנייה שבתיקייה `.github/workflows`. אם הפקודה `gh` לא מוכרת, התקינו את GitHub CLI מ-<https://cli.github.com>. לבדיקה: `gh auth status`.

## שלב 4: מפתח חתימה לאנדרואיד

אנדרואיד מקבלת עדכון לאפליקציה רק אם הוא חתום באותו מפתח כמו הגרסה המותקנת. אני מריץ פקודה אחת שיוצרת את המפתח ושומרת אותו ב-GitHub כסוד, בלי להציג אותו:

```bash
node scripts/setup-android-signing.ts
```

היא יוצרת שני קבצים בתיקייה `moked-secrets` בתיקיית המשתמש שלכם:

- `moked-release.p12`: קובץ המפתח.
- `moked-release-password.txt`: הסיסמה שלו.

**גבו את שני הקבצים עכשיו** במנהל סיסמאות או בכונן חיצוני. בלעדיהם אי אפשר לעדכן אפליקציה שכבר הותקנה, אלא רק להסיר אותה ולהתקין מחדש.

## שלב 5: התקנה

אחרי שאני מסמן גרסה, GitHub בונה את הקבצים ומפרסם אותם בעמוד <https://github.com/dofer12/desshbord-costumer-/releases>.

**באנדרואיד:**

1. מהטלפון, היכנסו לעמוד ה-Releases והורידו את `Moked-<גרסה>.apk`.
2. פתחו את הקובץ. אם אנדרואיד חוסם התקנה, לחצו **Settings** ואשרו **Allow from this source** לדפדפן. זה נדרש פעם אחת.
3. אם מופיעה אזהרה של Google Play Protect, לחצו **More details** ואז **Install anyway**. האזהרה מופיעה כי האפליקציה לא פורסמה בחנות.

**ב-Windows:**

1. מהלפטופ, הורידו את `Moked-Setup-<גרסה>.exe` מאותו עמוד.
2. הפעילו אותו. אם מופיע **Windows protected your PC**, לחצו **More info** ואז **Run anyway**. האזהרה מופיעה כי חתימה דיגיטלית למתקין עולה כסף.
3. האפליקציה נפתחת מעצמה ומתווספת לתפריט התחל בשם **Moked**.

## שלב 6: בסיס הנתונים למשימות (גרסה 0.2)

גרסה 0.2 מוסיפה את המשימות עצמן: רשימה, כרטיס משימה, תמונות והיסטוריה. הן צריכות טבלאות חדשות ב-Supabase, ולכן עושים את השלב הזה פעם אחת **לפני** שמתקינים אותה, גם אם כבר התקנתם את גרסה 0.1. הוא לוקח כרבע שעה.

1. **הריצו את קובץ ה-SQL השני.** ב-**SQL Editor** לחצו **New query** והדביקו את כל התוכן של הקובץ `supabase/migrations/0002_core.sql`. לחצו **Run**. אמורה להופיע ההודעה **Success. No rows returned**. מריצים פעם אחת בלבד, ורק אחרי `0001_profiles.sql`. אם מופיעה ההודעה `relation "statuses" already exists`, הקובץ כבר הורץ ואין צורך להריץ אותו שוב.
2. **ודאו שנוצרו הטבלאות והדלי.** ב-**Table Editor** אמורות להופיע, לצד `profiles`, הטבלאות `tasks`, `attachments`, `task_events`, `statuses` (17 שורות) ו-`app_settings`. ב-**Storage** אמור להופיע דלי בשם `task-files` עם הסימון **Private**.
3. **ודאו שתי הגדרות של ההתחברות.** ב-**Authentication**, ב-**Sign In / Providers**: המתג **Allow new users to sign up** כבוי, והשדה **Minimum password length** (בהגדרות של **Email**) הוא 10 לפחות. בדיקת האבטחה שבסעיף הבא בודקת את שתיהן. אם לא מצאתם את השדה, דלגו על הסעיף הזה והריצו את הבדיקה: היא תגיד אם הסיסמה הקצרה התקבלה.
4. **הריצו את בדיקת האבטחה.** היא יוצרת בפרויקט ארבעה משתמשי בדיקה זמניים: מנהל, שני עובדים ועובד שהושבת. בשם כל אחד מהם, ובשם מי שלא מחובר, היא מנסה כל פעולה שמותר או אסור לעשות: לקרוא, ליצור, לשנות ולמחוק משימות, תמונות, היסטוריה, סטטוסים, הגדרות ופרופילים, לפתוח ולמחוק קבצים בדלי ולקבל עדכון חי. בסוף היא מוחקת את כל מה שיצרה. היא לא נוגעת בנתונים שלכם, והריצה נמשכת כדקה.
   - העתיקו את **Secret key** מ-**Project Settings** ואז **API Keys** (מתחיל ב-`sb_secret_`).
   - פתחו טרמינל בתיקיית הפרויקט (בפעם הראשונה בתיקייה הריצו קודם `npm ci`) והריצו:

     ```bash
     node supabase/tests/security-check.ts
     ```

   - כשהיא מבקשת **Secret key**, הדביקו אותו ולחצו Enter. הוא לא מוצג על המסך, לא נשמר בשום קובץ ולא מודפס. כשהיא מסתיימת, סגרו את הטרמינל.
   - התוצאה הרצויה היא השורה האחרונה: `ALL CHECKS PASSED.` (הפלט באנגלית, כדי שאפשר יהיה להעתיק אותו כמו שהוא).
   - אם מופיע `THE CHECK FAILED`, אל תתנו לאחרים להשתמש באפליקציה. שלחו לי את כל הפלט (אין בו מפתחות) ואתקן. אם הריצה נעצרה באמצע, למשל כי סגרתם את הטרמינל, הריצו אותה שוב: היא מוחקת קודם את מה שהריצה הקודמת השאירה.
   - מריצים אותה שוב אחרי כל שינוי בהרשאות של בסיס הנתונים.

> **חשוב:** את המפתח הסודי מקלידים או מדביקים רק בטרמינל הזה. לא בצ'אט, לא בקובץ ולא באתר. אם הדבקתם אותו במקום אחר בטעות, צרו מפתח חדש ב-**API Keys** ומחקו את הישן.

## בדיקת קבלה לגרסה 0.1 (כניסה)

בצעו כל סעיף בלפטופ ובטלפון. אם משהו לא עובד, כתבו לי איזה סעיף ומה ראיתם.

- [ ] נפתח חלון **יומן משימות מוקד** עם מסך כניסה בעברית.
- [ ] כניסה עם המשתמש הראשון מציגה **שלום,** ואחריו החלק שבאימייל שלפני ה-@ (בשלב הזה השם נלקח מהאימייל), **תפקיד: מנהל**, את הגרסה ואת כתובת השרת.
- [ ] סגירה ופתיחה מחדש של האפליקציה מכניסה ישר, בלי להקליד סיסמה.
- [ ] סיסמה שגויה מציגה **האימייל או הסיסמה שגויים.** והטופס נשאר פעיל.
- [ ] התנתקות מחזירה למסך הכניסה.
- [ ] ניתוק האינטרנט, סגירה ופתיחה מחדש מציגים תוך כמה שניות **אין חיבור לשרת** עם הכפתור **נסו שוב**, ולא את מסך הכניסה. אחרי חיבור האינטרנט, לחיצה על **נסו שוב** נכנסת.
- [ ] ב-Supabase, בטבלה **profiles** יש את המשתמש שלכם עם `role` = `admin`.

## בדיקת קבלה לגרסה 0.2 (משימות)

בצעו כל סעיף בלפטופ ובטלפון, אחרי שלב 6. אם משהו לא עובד, כתבו לי איזה סעיף ומה ראיתם.

- [ ] אחרי הכניסה נפתח מסך **משימות** עם הכפתור **משימה חדשה**.
- [ ] בלפטופ: **משימה חדשה**, מילוי **שם לקוח** ו**מזהה שיחת Glassix** (או הסימון **אין שיחה ב-Glassix**), ו**שמירה**. המשימה מופיעה ברשימה, ותוך כמה שניות גם בטלפון, בלי לרענן. אותו דבר בכיוון ההפוך, מהטלפון ללפטופ.
- [ ] שמירה בלי פרטי לקוח, או בלי מזהה שיחה ובלי הסימון, לא נשמרת, והודעה בעברית מופיעה ליד השדה.
- [ ] שיוך לעובד, **תאריך**, **שעה**, **תזכורת** ו**עדיפות** נשמרים. הבחירה **המשימות שלי** ברשימה מציגה רק את המשימות המשויכות אליכם.
- [ ] **בוצע** מעביר את המשימה ל**בוצעו**, ו**סימון כלא בוצע** מחזיר אותה לפתוחות.
- [ ] חיפוש לפי שם לקוח, טלפון או מספר הזמנה מוצא את המשימה, גם אחרי שבוצעה (דרך **חפש בכל המשימות**).
- [ ] במשימה מסוג **איסוף** חובה למלא **שם מוצר**.
- [ ] בטלפון, בכרטיס של משימה שמורה: **צלם** פותח את המצלמה, והתמונה שצולמה נשמרת ומופיעה תוך כמה שניות. **מהגלריה** פותח את הגלריה. לחיצה על תמונה פותחת אותה בגדול. במשימה מסוג איסוף, **קבע כתמונת מוצר** בתצוגה הגדולה מציג אותה קטנה בכרטיס.
- [ ] בלפטופ: צילום מסך שהועתק (Win+Shift+S) ו-Ctrl+V בכרטיס מוסיפים אותו כתמונה.
- [ ] **היסטוריה** בכרטיס של משימה שמורה מראה מי עשה מה ומתי, כולל הוספת תמונה.
- [ ] **מחק משימה** מבקש אישור, ואחרי **כן, למחוק** המשימה נעלמת מהרשימה, גם במכשיר השני.
- [ ] ניתוק האינטרנט, עריכה ושמירה של משימה מציגים **שינוי אחד ממתין**. אחרי חיבור האינטרנט השינוי נשלח וההודעה נעלמת.
- [ ] משתמש שכיבתם את העמודה `is_active` שלו בטבלה **profiles** לא רואה שום משימה.
- [ ] בדיקת האבטחה (שלב 6) הסתיימה ב-`ALL CHECKS PASSED.`
